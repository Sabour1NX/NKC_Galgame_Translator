先前误区：碎片化并发

早期试用反馈出现文本切得过碎、字段粘连、闪动与局部规则失效。若先任意切屏再并发识别，文字上下文和阅读顺序可能被破坏，还会增加调度、重复工作和合并成本。

当前路径是先完整发现，再按真实词框、列边界和分隔线细化；输出按源顺序合并。线程实验没有重现“线程越多，识别内容越散”，因此不能把所有旧问题归因于线程数。

避免场景适配过拟合

只围绕一张游戏截图反复调规则，可能在那一页看起来很好，换菜单或背景就失效。这里的“过拟合”指工程规则对特定场景过度适配的风险。

本次未重新训练 OCR 或 LLM 权重，也没有跨游戏留出测试集，因此没有统计意义上的模型过拟合结论。三场景分开披露，未改善和退步项同样保留。

05 / REPRODUCIBLE EVIDENCE

每一个大数字，都能找到分母。

对照：二色蝶 0.01.15 → 二色蝶 0.01.22 · 2026-11-18

同一台 Windows x64 电脑，24 个逻辑处理器，15.8 GiB 内存。CPU 系统标识：Genuine Intel(R) 0000。两版顺序运行，正常后台负载；结果为小样本观测，不作统计显著性或跨机器承诺。

重复 OCR：每场景 12 次 A→B→A，B 改变一个角落像素。变化 OCR：8 次不同像素输入。首段：12 次、固定 80 ms 模拟服务；共享首段：80 ms 部分响应、400 ms 后完成。没有真实 API 请求，不能作为 DeepSeek 模型速度结论。

线程实验：各场景预热一次、测量 6 次，每次清空裁切缓存，固定整帧扫描；内存为进程工作集抽样，不是峰值。截图精度：人工标注区域内 356 个字符，NFKC / 去空白 / 统一弯引号 / 保留大小写，按字符编辑距离计算。

公式：耗时减少 vs 等效处理速度提升

速度倍数 = 基础框架耗时 ÷ 调优后框架耗时。等效速度提升率 = (速度倍数 − 1) × 100%。耗时减少率 = (1 − 调优耗时 ÷ 基础耗时) × 100%。例如 50× 的速度，对应约 98% 的耗时减少；它们不是同一个百分比。

截图与数据的来源及适用范围

报告使用同一份 Space Rogue Classic 截图，识别结果直接来自各版实际代码；叠加框只是数据可视化，没有重绘游戏画面。精度指标包括分栏与阅读顺序，不等于纯字形模型准确率、定位 IoU 或翻译语义评分。公开报告含这组测试截图，不含游戏程序、密钥或私人译文档案。
