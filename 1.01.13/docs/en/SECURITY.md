# Security design and boundaries · 0.01.27

## 0.01.27 Display does not wait for web reference

`TranslationEngine.translate()` reads only completed `ContextAgent.peek(key)` reference and immediately sends a tool-free translation request using current source, supplied context and available history. Only after successful translation and network-slot release does `refresh()` attempt background research. New notes benefit later sentences, never revise an already displayed translation or enter overlay events.

At most one background task and no waiting queue. The key includes game, executable identity, source/target languages and supplied context; 32 cached entries, 900 seconds with a summary and 30 seconds for empty/failed references. Background work shares concurrency, request/token accounting and cancellation, yields to waiting display jobs and does not use the sole slot when concurrency is one. Remaining budget favors translation. Closing cancels transport and joins the background worker.

Research failure cannot discard successful output. Background authentication/balance errors become unavailable with cooldown; errors in display requests still surface normally. `searching` denotes background work; `searched` requires final server-source evidence. Source/history/pages/notes remain untrusted JSON data: no local tools, automatic returned-URL fetches or credentials in prompts.

Version 0.01.27 adds optional CUDA OCR, background context and group font fitting. Fresh same-image OCR evidence compares 0.01.15 with 0.01.27, separating cold startup, changed-background warm paths, cached revisits and character accuracy; real-API observations are separate. Historical evidence retains its original version labels. See the current performance and test reports for scope.

## 0.01.27 context boundary

The optional background context layer uses the single DeepSeek server-side search tool; display translation requests have no tools and do not wait for new search. Both layers share request/concurrency/token accounting. Source text, excerpts, pages and notes remain untrusted. Returned links are never fetched by the client and cannot change source geometry. See [CONTEXT_AGENT.md](CONTEXT_AGENT.md) for exact payload, metadata, timeout and cache contracts.

Compatibility review: 0.01.27 · 18 November2026. Historical sections retain their original version numbers.

## 0.01.27 selection and font boundaries

The union frame is retained locally for capture/background reconstruction. Gaps are blacked out before OCR or optional Vision upload. Only lines contained by one selection are admitted. Font selection uses installed faces, checks target-script and actual glyph coverage, and downloads no fonts. Geometry, counts and caches are bounded.

This describes implemented controls and remaining limitations, not a security certification or an independent audit. Treat game text, OCR output, imported dictionaries and model responses as untrusted data. The selected API provider necessarily receives the configured credential and requested text. A locally compromised Windows account or writable installation is outside the protection promised here.

## Pixel overlay and game access

The application captures the selected game's visible client area and creates its own click-through overlay windows. It does not inject a DLL, hook game code, inspect/write game string memory or require administrator access. The former memory mode was removed. A target is bound by HWND and PID; capture and rendering are hidden/suspended when the intended target is unavailable or loses foreground focus. This does not certify compatibility with every game's terms or anti-cheat software.

The renderer uses background colors sampled near text, not scene reconstruction. It masks only the laid-out translated portion during a stream, then the complete source rectangle at completion. Missing/failed results leave the source visible. Fonts are selected from Windows font families; no downloaded font or font-file execution facility is added. Font measurement and rendering use the same family. Input validation and fixed layout bounds reduce accidental resource abuse but do not eliminate all native or font-engine risks.

## Prompt/data boundary

Each text-translation request contains one fixed trusted system instruction. Source/target language, context and text are JSON-serialized fields in a user data record. Game text, profile names, term content and context never become a second system message. Language/model identifiers have explicit validation. Historical references are serialized data; new output is generated by AI without local substitution.

The translation request contains no tools. The separate optional context request declares only DeepSeek server-side web search; the client has no command, script or local function executor. Responses are only displayed and stored. Instructions embedded in a game string are text to translate, not authorization for application actions. This separation reduces prompt-injection exposure; it cannot guarantee semantic accuracy or prevent a model from producing undesirable words. An incorrect accepted result can become a dictionary entry. Review or delete affected entries and use scope/revision controls to invalidate dependent cached results.

## Endpoint and credential handling

Three key slots use Windows current-user DPAPI. The encrypted record is bound to the canonical complete API base URL, including its path. Changing that address requires a key to be entered/bound for the new endpoint. Older unbound records are retained without being silently activated. Plaintext legacy keys are encrypted during supported migration and are not automatically authorized for a new address.

ConfigStore validates settings before persistence, uses temporary-file/atomic-replace operations and a recovery journal for related files. The UI does not display plaintext secrets after saving. DPAPI protects stored bytes against routine copying to another account/computer; it is not a password vault against code already running as the same Windows user. Keep private configuration outside public ZIPs, email attachments and source control.

API URLs must use HTTPS, have a valid public-style host and no user information, query, fragment, control characters or known local names/non-public IP literals. Validation does not perform DNS and cannot prevent DNS rebinding or prove provider trust. The built-in HTTPX client uses certificate verification, `trust_env=False` and no redirects. Environment proxy/certificate variables are not inherited. A caller-supplied transport is the caller's responsibility; request redirect following remains disabled. The URL rules do not support loopback/LAN API endpoints in this release.

## Bounded network and file input

| Boundary | Implemented restriction |
|---|---|
| SSE | Identity encoding only; strict UTF-8; 128 KiB physical line, 256 KiB data event, 2 MiB total, 20,000 physical lines and 8,192 data events. |
| Output | At most 64,000 characters; no NUL, unpaired surrogates or unexpected controls; nonempty result, stop finish reason and complete DONE event required for success. |
| Requests | Concurrency 1–16, timeout 1–120 seconds, retries 0–2; each attempt is counted. Finite mode enforces its 0–10000 allowance; the separate unlimited switch bypasses only that count cap. Request limits are not a monetary cap. |
| Dictionary files | At most 20 MiB and 100,000 entries; bounded fields/structure; explicit supported formats and encoding; SQL parameters rather than interpolated SQL. |
| TMX | No DTD/entity declarations, restricted XML structure/depth/languages; no arbitrary external XML fetch. |
| Paths | Ordinary local files only where the helper/path contract requires them; reject device/network/ADS/reparse-point paths. |
| OCR | Private bounded BMP frame, explicit BMP decoding, raw RGB handed to Tesseract; bounded JSON IPC and numeric/geometry validation. |

Malformed/truncated output is not committed as a complete translation. Error messages use controlled descriptions and status codes rather than provider response bodies. Cumulative partial text is cleared on failure. See [API.md](API.md) and [INPUT_INTERFACES.md](INPUT_INTERFACES.md) for exact per-field contracts and lifecycle constraints.

## Native and supply-chain controls

The x64 DLL uses stack checks, `/sdl`, Control Flow Guard, ASLR, DEP and high-entropy VA flags. Python declares exact ctypes signatures and verifies ABI 2 plus the new `gl_set_font` export. These measures do not prove absence of memory bugs. A matching ABI number alone is insufficient for mixing an older DLL with the new font wrapper.

Dependencies are version/hash locked for CPython 3.14 Windows x64. Published packages contain their licenses, component inventory, source acquisition materials and file hashes. Build paths are passed as argument arrays, not generated shell statements. Hashes detect changes relative to the supplied manifest; without an independently trusted signature/source they do not authenticate a publisher. This release is not code signed.

The OCR wheel reports OpenJPEG 2.5.4; its patch state cannot be inferred from that version string. The BMP/raw-RGB-only path reduces this application's exposure without certifying the binary. Opening additional image formats requires another review. Python advisory-query results do not cover every native dependency or unknown vulnerability.

## Diagnostics and release privacy

Startup reports contain a controlled message, exception type and at most eight sanitized basename/line/function frames. They omit exception bodies, source lines, locals, full paths, environment values, API keys and screen pixels. Reporting failure does not recursively log itself. The application has no runtime telemetry, automatic model downloader or updater.

The public packaging allowlist excludes personal configuration, keys, translation databases, logs, screenshots, private demos and game assets. A private demo may intentionally use a locally authorized encrypted credential; it must remain separately labeled and must not become the public package. Review any diagnostic or screenshot before sharing. Personal report-email and idle-shutdown tasks are not public application startup features.


## Optional image-recognition data boundary

Default OCR is local and vision_ocr defaults to false. When explicitly enabled, the current API provider receives the selected game-region image and recognition hints; this release must not be described as never uploading screenshots under any circumstances. Capture is bound to the selected target/region. Images are inline PNG data URLs, with no File API, arbitrary external image URL, entire-desktop upload or game-file upload. The selected region can itself contain personal information, and the provider handles sent requests under its own terms.

The model returns only existing local-box IDs and text, never new coordinates, clicks, scripts or executable links. Image/hint contents are untrusted data under fixed transcription instructions. Bounded UTF-8 JSON, known IDs, duplicate-field rejection, text limits and local geometry constrain output without guaranteeing transcription/semantic accuracy. Requests share translation concurrency/allowance. Canceling prevents display but cannot reclaim charges for an already sent request. Exact resize, response, cache and fallback contracts are in the API/input chapters.

## 0.01.20 history and opaque backgrounds

Local source/result/context/reference events are private records; zlib compression is not encryption. Budgeted history excerpts are sent to the selected API. Fixed system/JSON separation does not prove immunity to prompt injection; output is text and is never executed. Scope sidecars contain only hashes/statistics/time, while SQLite requires private-data handling. Aero uses the selected game capture only; it does not sample other applications to fill backgrounds.
