# 用户指南 · 0.01.27

## 0.01.27 整组拟合与短续行

同一段正文以源行墨迹高度的中位数作稳定参考。至少三行且有至少两条宽正文、宽正文占多数时，极短续行或明显低墨迹行不单独把整组压成极小字号。单个 Region 内，短续行溢出可尝试把完整字簇分配到紧邻前行已测得的空余宽度，最多检查 64 个候选且续行至少保留一簇；行框不扩大。不能容纳的弱证据行保留原文字像素。跨 Region 不挪动文字；普通、中宽长译文仍约束共同字号。

流式阶段显示当前参考字号能容纳的前缀，完整译文仍累计保存；完成后再执行整组拟合和满宽字距。标题、列、源字号/风格、固定字号与显式字号上限边界保留。少数弱框可能仍显示原文，流式尾部可能等到 final 后出现。这是显示修复，不代表 OCR 或语义翻译准确率提高。

不新增用户配置，不改变 ABI 2 或原有导出签名；原生诊断新增 `font_intrinsic_px` 与 `lines[].drawable`。`fits=true` 表示可靠约束行已拟合，弱异常行仍可能 `drawable=false`，逐行可见性应检查该字段。本版 C++ 核心需要重新编译与验收，旧版 native audit 不构成本版二进制证据。

## 0.01.27 CUDA 识别与实际回退

首次语言设置和常规设置共用 CUDA 控件。`cuda_enabled` 默认开启；只在 OCR **自动模式**且源语言为英语、日语或中文时尝试 CUDA。手动 Windows / Pixel 模式明确走 CPU；自动模式检测到经典英语像素画面且便携识别可用时优先 CPU Pixel 路径（`pixel_priority`）；其他语言继续使用已有本地识别。组件缺失、无兼容 GPU、模型校验或推理失败时回退 Windows / Tesseract，并显示实际状态，不能把“文件已安装”当作“CUDA 已运行”。失败后的当前 OCR 实例不反复重试 GPU，修改设置后停止并重新开始。

| 设置 | 默认 | 范围与作用 |
|---|---|---|
| `cuda_enabled` | `true` | 开关；不自动下载或安装组件 |
| `cuda_quality` | `75` | 0–100，高性能到高精度；线性调节检测长边，按 32 像素量化 |
| `cuda_memory_mb` | `1024` | 256–16384 MiB；推理内存 arena 预算，不会强行占满 1 GiB，运行库和驱动另有开销 |

检测长边约为 `768 + 11.52 × cuda_quality` 后按 32 像素量化；75 对应 1632 像素。仅缩小超出上限的图像，小图在不同档位可能等效；数值不是准确率百分比，也不保证单调提速或提高精度。CUDA 模型为 PP-OCRv6-small，GPU/依赖验证结果以本版报告为准，不提前声称所有 NVIDIA 显卡可用。

启用可选云端 AI 图像精读时，CUDA 已输出的行仅在置信度不低于 95 且没有拒绝标记时直接送译，其余仍走核验路径。**95 是模型分数门槛，不是 95% 实测准确率承诺**。CUDA 本地 OCR 不上传图片；云端精读仍遵循独立开关和图片发送规则。

## 选择实际游戏窗口

1. 先启动 `Windose.exe`，让 NEEDY GIRL OVERDOSE 的游戏画面出现，再刷新窗口列表。
2. 选择类似 **Windose · Windose.exe · PID 123** 的条目；PID 由系统分配，每次启动可能不同。相同名称的文件夹窗口属于 `explorer.exe`，不会作为翻译目标。判断依据是窗口与进程身份，不是标题中是否出现游戏名称；普通英语程序仍可选择。
3. 选择“整个游戏窗口”或手动框选 1–8 个区域，再点击“开始翻译”，然后切回游戏。窗口选择时会重新检查 HWND/PID；关闭或重启游戏后请刷新并重新选择。
4. 状态会指名目标窗口，区分后台等待、最小化、隐藏、窗口关闭或进程变化，以及实际识别、未找到文字、等待 AI 和已显示译文。**等待窗口表示尚未处理该游戏画面**；将目标游戏恢复并置于前台后继续，不会自动抢走焦点。

主界面顶部使用紧凑 API 配置工具栏，不再占用空间展示大图标、大标题与标语；窗口/任务栏图标保留。遇到实际错误时错误信息保留至停止或重新开始，不会被普通状态刷新掩盖。


0.01.27 加入可选 CUDA OCR、后台联网语境与整组字号修复。本版新增同图 OCR 评审，对照 0.01.15，分别报告冷启动、背景变化热路径、复访缓存和逐字精度；真实 API 链路另列。历史证据保留原版本标签，当前方法与范围见性能报告及 TEST_REPORT.json。

## 游戏翻译 Harness：理解与显示分层

二色蝶把模型放在有边界的游戏翻译流程中：程序管理原文与坐标、语境参考、请求额度、对象修订和原位显示，模型负责理解与译文。质量优先意味着先验证文本完整性和定位，再考虑缓存与调度；增加识别步骤或联网参考可能增加等待时间。

| 层 | 模块 | 负责什么 | 不交给下一层什么 |
|---|---|---|---|
| 感知层 | `OcrCore` / OCR helper / `RegionRefiner` | 整图发现、已定位区域精读、原图词框与墨迹；保留选区边界 | 不凭模型推测坐标，不随机切碎画面后拼接 |
| 上下文层 | `ContextArchive` / `ContextAgent` | 压缩历史、术语与有界摘录；可选 DeepSeek 联网背景参考 | 搜索进度、推理和来源不送入覆盖显示 |
| 译文层 | `TranslationEngine` | 使用当前原文及参考生成纯文本；有界 SSE、并发与预算 | 无布局命令，不调用本地代码 |
| 显示层 | `OverlayState` / C++ `fixed_layout.h` | 修订检查、原位源行、段内统一字号、满宽字距、流式遮挡 | 不用背景摘要代替原文译文，不改变游戏状态 |

在“设置 → 上下文层与显示层”可开启联网理解游戏背景；公开默认关闭，保存后重新开始翻译。仅官方 DeepSeek `deepseek-flash` 的已支持服务端搜索接口使用此扩展，其他兼容服务仍可普通翻译。模型决定是否搜索，界面区分实际取得来源与未搜索；启用开关不代表每次都进行了搜索。背景参考缓存不替代后续译文请求。[联网理解接口与费用边界](CONTEXT_AGENT.md)。

同一连续正文组保持统一字号。短译文完成后仍可增大字距填满原行；长行在自动范围内要求缩字时，同组一起缩小，不能只放大其中一行。标题、不同源字号、不同列和字体风格保持独立；达字号下限仍放不下时保留原文。坐标来自本地 OCR，字号一致不代表错误的 OCR 框已经被修正。

当前实际游戏测试改用 NEEDY GIRL OVERDOSE，关注日文小字、多色面板和段内字号；既有 Space Rogue 固定截图保留为回归材料。测试范围、计时和剩余限制以本版测试与性能报告为准，不把一张图的结果推广为全游戏结论。

适用版本：0.01.27 · 文档复核：2026-11-18。历史记录保留原版号。

## 多区域与自动字体

在屏幕翻译页选择游戏窗口，点击“框选区域”。连续拖动添加 **1–8 个不重叠矩形**；按 **Enter 确认**，按退格或右键撤销最后一个，Esc 取消并保留原选择。每框至少 20 × 20 像素；合并外接矩形每轴不超过 4096 像素。请把一整段文字留在同一框内，并留少量边距。区域随游戏客户区移动，缩放后裁到客户区；更换游戏窗口后恢复整个客户区。选区仅在本次界面会话保留。

多个选区使用同一帧捕获，框外间隙先遮成黑色再进入 OCR 或可选 AI 图像精读；语句团和对象关联不跨选区。框选不同区域不会分别启动多个 OCR 进程，也不改变翻译并发上限。全屏游戏建议切换窗口模式。

打开“设置 → 译文外观 → 按原文自动选择相似风格字体（支持目标语言）”，保存后重新开始翻译。程序根据原文字形近似选择像素、衬线、无衬线或等宽风格，并逐框检查字体是否支持目标语言与当前译文字形。无需下载字体。默认关闭，关闭时仍使用手动字体。自动字号及上下限独立设置，过长译文继续在允许范围内缩小。

字体匹配不等于还原游戏字体；装饰字、复杂背景、短词和误识别可能影响风格判断。字形不全时改用已安装且覆盖译文的后备字体；没有合适字体时保留原文。当前自动覆盖检查保守支持 BMP 字符；含补充平面字符或 emoji 的该框保留原文，可切回手动字体使用 Windows 字体回退。

更新：2026-11-18。先在顶部 API 三槽位配置可用服务，然后选择游戏窗口、源/目标语言、可选游戏档案与选区，点击开始翻译后切回游戏。界面语言与游戏语言独立；首次按 Windows 用户语言预选，设置可切换中文、English、日本語。协议确认由用户主动完成。

## 画面与定位

先识别完整选区，再多线程细化已发现对象。将选区覆盖整段对话或完整面板有助于判断列和语句团，但不要包含桌面或无关应用。自动/标准/像素 OCR 可选；多列正文按列关联，明显横线、价格列与菜单项作为边界。全帧识别不保证每个像素字体都能读出，未识别或疑似错误的原文字不被猜测覆盖。

Aero 覆盖以保留原背景结构为先：只对具有前景颜色与抗锯齿证据的字形像素建立掩模，并在掩模内用邻近背景局部修补；底图中掩模外 RGB 保持逐像素不变，不整行模糊或添加高光。覆盖完全不透明，译文再绘于其上。无法可靠区分字形与同色背景图形时保留原画面并抑制该框译文；被字遮住的细节仍只能近似修补。

每个源行独立显示，行间与价格保持原画面。译文较长自动缩小，较短完成译文调整字距；字体缺失时Windows可能回退。

## 纯 AI 与历史

新的有效翻译都请求 AI。词典、旧译文和用户语境作为参考发送给模型，不作本地替换。没有 API 时只能浏览存档；不要把保留的游戏原字误认为翻译结果。静止已翻译对象复用当前显示，同一时刻的相同请求可合并，之后手动再次提交仍会调用 AI。

“翻译词典”页可维护历史术语与导入文件，并查看“译文与语境档案”的最近 24 条记录。保存内容含原文、完整译文、语境、模型与时间。按游戏档案/语言对隔离；没有档案名时使用所选可执行文件身份隔离。

## 可调参数

默认 OCR 细化线程 4（1–8）、翻译并发 8（1–16）、匹配线程 2（1–4）。增加线程不保证线性提速。历史语境字符预算默认 6000（512–16000），记录上限默认 24（1–64）；过往完整记录仍在数据库，只有下一次请求的摘录被限制。

来源标签、仅同屏多外文时标注、方括号互相独立。API 请求额度与无上限开关独立于并发。关闭无上限后额度 0 表示禁止新请求。保存网络和线程设置前停止翻译并等待旧任务结束。

## 文件与恢复

`data/codebook.sqlite3` 保存历史与压缩语境，`data/contexts/<scope_id>/updated.json` 自动记录更新时间和大小，时间带 `+08:00`。不应仅备份 JSON 而遗漏数据库。旧版本目录保留，不自动重命名正在运行的版本目录。复制数据库时先关闭应用，或使用 SQLite 备份接口。

停止/关闭立即撤下覆盖；鼠标按键应穿透至游戏。失焦隐藏覆盖。无输出时依次检查窗口/选区、前台状态、API 密钥、请求额度及错误提示。OCR 漏字可缩小到完整文字面板或切换像素模式。可选 AI 图像精读依赖模型图像能力，不支持时保留本地 OCR；不把当前模型名称视为图像能力保证。

## 0.01.22 · 响应速度 · 2026-11-18

在设置页顶部选择 **响应优先**，再保存设置；停止并重新开始翻译生效。新安装默认采用此组参数，升级时已有自定义值保留。个人 Space Rogue 演示已单独应用该组参数。

| 参数 | 响应优先（新默认） | 均衡占用 |
|---|---:|---:|
| 截图间隔 | 50 ms | 250 ms |
| 文字稳定等待 | 80 ms | 450 ms |
| 翻译并发 | 8 | 4 |
| OCR 区域细化线程 | 4 | 2 |
| 漏识别保留帧数 | 10 | 2 |

保持名义 500 ms 漏识别保留窗口。CPU 忙时帧耗时会改变实际保留时间。可逐项修改；逐字显示的对话建议延长稳定等待，避免中间文本触发额外 API 请求。更高并发会增加瞬时负载，遇到 429 可降低并发。请求次数限制与该预设相互独立。

像素模式的 AUTO 与 SPARSE_TEXT 整帧扫描并行进行，始终按主扫描、补充扫描顺序合并，随后再并行细化真实文字框。各线程使用独立 Tesseract 引擎。256 项识别缓存只复用相同裁切像素、尺寸、语言、原始识别文字和置信度对应的细化文字；位置永远来自当前帧。换字、换语言、置信度变化会失效，失败结果不缓存。此缓存不保存或代替 AI 译文。

流式翻译进行时，UI 最短每 8 ms 消费事件，空闲时为 80 ms；仍按线程队列传递，不从工作线程操作 Tk。连接池保留空闲连接最长 60 秒，仍不跟随重定向且不读取代理环境。后台服务可提前关闭连接；这不是固定网络延迟承诺。

性能测量、首次加载代价及测量边界见 [性能报告](PERFORMANCE_REPORT.md)。原位字体拟合、点击穿透、拖动跟随和过期结果拦截继续保留。
