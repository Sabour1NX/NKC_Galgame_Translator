# 二色蝶 0.01.15 基础框架 → 0.01.22 调优后框架

2026-11-18，同一台电脑，Space Rogue Classic 三张原始截图。0.01.15 是目前保留的最旧版本，也是“本轮响应优化前”的产品基线；不是未经改动的第三方原装框架。没有竞品实测或排名。

查看 [交互式性能报告与截图对照](PERFORMANCE_REPORT_0.01.22.html)。所有百分比从本次数据计算，不沿用 0.01.21 的数字。

## 指名道姓的框架对照

两版共同依赖：CPython 3.14.10、Tkinter / Tk 9.0、Tcl 9.0.4、C++17 / Win32 / GDI / C++/WinRT 原生模块、Tesseract 5.5.4 + tesserocr 2.13.0、httpx 0.28.1、Pillow 13.0.0。使用相同英语模型文件。本次 OCR 强制 pixel 模式；Windows OCR、AI 图像精读和线上 LLM 不在速度测量中。

| 部分 | 基础框架 · 二色蝶 0.01.15 | 调优后框架 · 二色蝶 0.01.22 |
|---|---|---|
| 整帧扫描 | AUTO / SPARSE 顺序执行 | 独立引擎并行扫描，按固定顺序合并 |
| 文字定位 | 行级识别，表格可能跨列 | 完整画面发现后，按实际词框/分隔线划分，再并行细化 |
| OCR 复用 | 无新版整帧复用层 | 16 项、128 MiB 预算整帧 LRU + 256 项裁切细化缓存 |
| 调度默认值 | 截图 250 ms / 稳定 450 ms / 翻译并发 4 | 50 ms / 80 ms / 8；二次捕获确认后复用已等待时间 |
| 相同网络请求 | 共享最终结果 | 在途部分结果也共享，先收到的首段先显示 |
| 翻译路线 | 可使用本地词典/专家/混合 | 纯 AI；历史仅作参考。本次共享测试强制网络未命中路径 |

## 速度对比：同一任务耗时的倒数

图表默认使用固定 150 ms 参考预算：实色 = max(0, 150 − 实际耗时)，透明部分代表占用时间；越快实色条越大。超过预算时显示超出量，不能据此比较完整端到端时限。等效速度选项仍使用下述原始耗时倒数。

等效处理速度倍数 = 基础版耗时 ÷ 调优版耗时；速度提升率 = (倍数 − 1) × 100%。耗时减少率 = (1 − 调优版耗时 ÷ 基础版耗时) × 100%。不是实际游戏 FPS，不是在线全流程吞吐量。

| 返回相同画面 OCR（各 12 次中位数） | 0.01.15 / ms | 0.01.22 / ms | 等效速度倍数 | 等效速度提升 |
|---|---:|---:|---:|---:|
| 剧情页 | 360.791 | 9.440 | 38.22× | +3721.9% |
| 状态菜单 | 86.569 | 7.713 | 11.22× | +1022.4% |
| 货物价格表 | 137.993 | 2.733 | 50.49× | +4949.1% |

新版本命中完整 RGB 像素缓存；A→B→A 的 B 改变角落像素。两版均已有连续静止帧跳过机制，不能以此冒充新版收益。每项仅指 OCR 结果返回，不包括 API 翻译。缓存核对完整像素、尺寸、模式、语言和阈值；最大 128 MiB 是计费预算，不是进程总内存上限。

固定 80 ms 模拟服务，零耗时 OCR：首段回调 703.87→185.45 ms，等效速度 +279.5%，耗时减少 73.7%。相同在途请求跟随框 497.88→82.63 ms（模拟首段 80 ms、400 ms 后结束）。不包括实际网络和显示，不能宣称 DeepSeek 或任一模型因此提速。

## 截图精度：区域内文字和阅读顺序

人工标注区域内，共 356 个标准化字符；字符编辑距离 57→37，分区字符准确率 83.99%→89.61%，提升 **5.62 个百分点**，错误数量减少 **35.1%**。主要改善是货物表的商品/价格分栏。剧情和状态菜单未提高，选中行与部分像素字体仍有漏识别。

按框中心归属人工标注区，区内按 y/x 排序；先 NFKC、去空白、统一弯引号，再计算 Levenshtein 距离，大小写敏感。因跨列合并会影响阅读顺序，此指标同时反映分区/分栏效果，不能说成只提升了字形识别模型。截图中的框和文字来自真实输出 JSON；不使用生成式图片加工。不是译文语义质量、IoU 或跨游戏精度。条纹遮挡 HELP 和状态日期数字未纳入样本。

## 线程不是越多越好；避免场景过拟合

早期用户反馈包括切分碎片、粘连、闪动与对特定画面过度适配，可作为工程上的场景过拟合风险。模型权重没有重新训练；没有独立跨游戏留出集，不能声称已证明训练模型过拟合。

本次额外测试 0.01.22 的 1/2/4/8 个细化线程：每组 3 场景，各预热一次再测 6 次，清空裁切缓存，保持整帧识别和合并顺序不变。四组的文字与框坐标哈希完全一致，因此没有证据表明本版线程增加会使字段识别变散。8 比 4 线程在货物页略慢，工作集抽样约多 35%；剧情页略快。默认 4 是折中，并非所有电脑最优。

修正思路：先识别整体再并行细化；按实际文字对象分组；固定结果合并顺序；有界线程池/裁切预算；真实新画面与重复画面分开测。报告保留慢下来的场景与未改善的精度，避免只对一张演示图调参。

## 测量边界

变化画面每场景 8 次、缓存强制失效，详见图表和 JSON；状态菜单的变化画面反而更慢。同机按先旧后新顺序，正常后台负载，未做统计显著性或跨机器结论。OCR 表使用同一 CPython 运行时加载各版源码、各自原生模块和同一模型。线程实验只测 helper，不能与完整 OcrCore 延迟混算。峰值内存未测，仅列工作集抽样；冷启动只有单次观察。

公开报告包含用户要求的 Space Rogue 截图证据，不含游戏程序、私人密钥或历史档案。原始样本和框数据见 PERFORMANCE_REPORT_0.01.22.json；复现脚本为 tools/compare22.py、response_benchmark.py、shared_stream_benchmark.py、thread_study.py。真实 API 请求次数为 0。
